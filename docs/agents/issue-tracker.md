# 任务跟踪

本项目已有 GitHub 远端，当前仍使用仓库内的 Markdown 文件记录规格与任务，目录为 `.scratch/`。若管理者决定改用 GitHub Issues 等服务，再更新本文件与任务记录方式。

## 文件约定

- 每项功能使用一个目录：`.scratch/<功能标识>/`。
- 功能规格写入 `.scratch/<功能标识>/spec.md`。
- 实现任务分别写入 `.scratch/<功能标识>/issues/<序号>-<任务标识>.md`，序号从 `01` 开始。
- 任务状态写在文件顶部的 `Status:` 字段；可使用 `ready-for-agent` 表示已准备好实施。讨论记录追加到 `## 讨论` 小节。
- 相关 skill 要求“发布到任务跟踪系统”时，在上述目录创建对应文件；要求“读取任务”时，按用户提供的路径读取文件。

任务与规格均使用中文撰写。

## 任务完成与提交

- 一项任务完成后先执行该任务的验收检查，记录结果并更新任务状态，然后提交该任务涉及的代码、测试和必要文档。
- 提交范围按任务划分；开始下一项任务前，前一项任务的改动应已提交。不得把多个任务积攒到一个提交，也不得把工作区原有的无关修改带入。
- Git 提交消息使用中文并遵循 Conventional Commit 规范。若任务需要多个有独立意义的提交，可以在同一任务内分次提交，但每个提交仍须保持范围清晰。
