# 个人管理第二批业务闭环规格

Status: ready-for-agent

## 问题陈述

项目、任务、完成历史和“今日任务”已经可用，但管理者还不能设定习惯、补记打卡、写每日记录、在“今日”处理这些内容、查看每周回顾或手动导出私人数据。第一阶段的个人管理入口因此尚未闭环。

依据：[功能范围](../product-scope/spec.md)、[技术实施规格](../technical-plan/spec.md)、[验收边界](../technical-plan/testing-plan.md)、[领域术语](../../CONTEXT.md)、[完成历史 ADR](../../docs/adr/0010-preserve-task-completion-history.md)、[上一批规格](../project-task/spec.md)。

## 解决方案

在现有唯一管理者的私人 API 和管理端中，依次交付习惯设定与暂停、按日期打卡和统计、每日记录、完整“今日”、每周回顾、第一阶段数据导出。任务完成记录、习惯打卡和每日记录保持独立存储，在日期页面和回顾中并列展示。所有业务日期按 `Asia/Shanghai` 解释。

## 用户故事

1. 作为管理者，我希望创建每天执行或每周灵活完成指定天数的习惯，以便安排不同节奏。
2. 作为管理者，我希望修改习惯名称和目标、暂停与恢复习惯，以便适应计划变化且保留既有记录。
3. 作为管理者，我希望按某个日期标记完成或未完成并写备注，以便记录实际执行情况。
4. 作为管理者，我希望补记过去日期和纠正误打卡，以便历史准确。
5. 作为管理者，我希望在日历中看到打卡、未打卡和暂停日期，以便理解周、月完成率。
6. 作为管理者，我希望每天写一篇可反复修改的 Markdown 每日记录，以便记录当天的事情。
7. 作为管理者，我希望在某天的记录旁看到当天任务完成事实和习惯打卡，以便回看当天情况。
8. 作为管理者，我希望在“今日”同时看到任务、待打卡习惯和当天每日记录，以便集中处理。
9. 作为管理者，我希望每周查看任务完成历史、习惯执行情况和每日记录，以便回顾这一周。
10. 作为管理者，我希望手动导出第一阶段的项目、任务、任务完成历史、习惯、打卡历史和每日记录，以便自行留存。
11. 作为管理者，我希望这些内容只对自己可见，且并发修改发生冲突时保留编辑输入，以免丢失数据。

## 实施决策

- 沿用现有唯一管理者 Session、CSRF、来源校验、错误响应、版本冲突、OpenAPI → TypeScript 生成链和 `mise run ci`。业务主键继续使用 PostgreSQL `BIGINT IDENTITY`，对外为十进制字符串。
- 习惯具有每天执行或每周指定天数两种目标。每周从上海时间周一开始；日期只保存 `DATE`，事件时间另存 `timestamptz`。习惯设定的历史变动需要有生效日期或等效快照，使旧周、旧月统计不会被后续修改重写。
- 习惯暂停记录日期区间，可恢复；暂停日期不属于应执行日期，不能在暂停日期打卡。未暂停的过去日期缺少打卡按未完成计，尚未到来的日期不计入当前完成率。创建前的日期不计入统计。
- 每天习惯的周、月完成率以已到来的应执行日期为分母。每周目标习惯按周统计：有效目标为该周目标天数与该周已到来的非暂停应执行日期数的较小值，完成次数最多计到有效目标；月完成率按每个相交周的达成率加权平均，权重为该周落在当月的已到来应执行日期数，避免跨月周重复计算目标。没有应执行日期时显示无统计值。跨月周、暂停、目标调整和部分当前周的边界由习惯统计任务通过实例锁定，避免只靠前端计算。
- 同一习惯和业务日期最多一条打卡；完成、未完成及备注可更正。打卡历史与习惯设定分开保存；管理者删除习惯时不能使既有打卡和回顾事实丢失。删除策略在习惯任务中固定为隐藏当前习惯、保留历史查询所需快照。
- 每个业务日期最多一篇每日记录。正文保存 Markdown 原文，复用任务说明的安全预览规则；保存采用预期版本。任务完成记录、习惯打卡只在日期页面旁展示，不自动写入正文。
- “今日”以现有任务查询为基础接入习惯与每日记录。服务端按 `Asia/Shanghai` 计算今天；未打卡习惯和逾期任务要有明确提示，不发送站外通知。
- 每周回顾按服务端确定的上海时间周一至周日查询；任务完成事实取既有历史，因此任务或项目删除后仍可见。习惯与每日记录依据各自历史展示，不产生新的操作审计。
- 首版手动导出采用下载 UTF-8 JSON，带格式版本与生成时间；输出第一阶段全部现有与保留的业务记录，包含已删除任务仍保留的完成历史。服务端使用一致性读取，导出仅对管理者开放；不把 Session、密码哈希、CSRF token 或其他认证秘密写入文件。

## 测试决策

- 以私人 HTTP 接口与隔离的真实 PostgreSQL 为主要验收边界，沿用现有认证、项目任务和完成历史测试方式。验证空库迁移、约束、并发版本、日期边界与删除后的历史。
- 用受控时钟覆盖上海时间跨日、周一、月末、跨月周和当前部分周；统计只核对用户可观察的结果，不镜像内部 SQL 或实现函数。
- 浏览器关键流程串联创建习惯、补记与暂停、编辑并预览每日记录、使用“今日”、查看每周回顾和下载导出文件。
- 每项任务独立通过其验收条件与 `mise run ci`，验收结果写回任务文件，然后单独提交。

## 范围之外

- 公开网站、文章、文件与媒体、访问统计和访客接口。
- 站外提醒、自动生成重复任务、复杂习惯评分、跨模块自动改写正文。
- 数据导入、定时导出和自动备份；生产镜像、部署和恢复演练在第一阶段上线批次单独拆分。
