# 实现每日记录与当日事实展示

Status: completed

## 目标

让管理者按日期创建和反复修改一篇 Markdown 每日记录，并在旁边看到当天已完成任务和习惯打卡。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[完成历史 ADR](../../../docs/adr/0010-preserve-task-completion-history.md)。

## 实施范围

1. 建立业务日期唯一的每日记录，提供按日期读取、创建和更新的私人 API；保存采用预期版本，正文保留 Markdown 原文。
2. 管理端提供日期选择、编辑、安全预览、保存和冲突提示；复用任务说明已验证的危险 HTML、链接协议和远程图片限制。
3. 日期页面并列展示当天任务完成记录与习惯打卡。任务或项目删除后仍从完成历史中展示已有事实；任何汇总都不自动插入每日记录正文。
4. 用上海业务日期查询记录及旁边事实；明确空日期的空状态，不创建无内容的占位记录。
5. 更新契约和真实数据库、浏览器关键流程测试。

## 验收条件

- 一个日期只有一篇每日记录；反复修改保留最后成功保存的正文，版本冲突返回 409 且页面保留编辑输入。
- 当天任务完成记录、习惯打卡按正确业务日期展示；任务删除或重新打开不改变既有完成事实，正文不被自动改写。
- Markdown 预览不执行危险 HTML 或脚本链接，也不加载未允许的远程图片。
- 私人鉴权、CSRF、上海跨日、真实 PostgreSQL HTTP 测试、浏览器流程与 `mise run ci` 通过。

## 依赖与交接

- 依赖任务 02 的打卡查询与上一批 06 的任务完成历史。
- 向“今日”、每周回顾和手动导出提供按日期查询的记录。
- 验收后记录检查结果，并单独提交。

## 验收记录

- 2026-09-27：每日记录以业务日期为主键；空正文与未来日期不创建占位记录。新建使用空预期版本，编辑使用当前版本，冲突保留管理端输入。
- 日期页并列读取独立的任务完成快照与习惯打卡；正文只保存 Markdown 原文，预览复用现有安全渲染组件。
- `mise run ci` 通过，包含真实 PostgreSQL 跨上海零点、版本和删除后快照测试，以及浏览器危险内容预览、保存与冲突流程。
