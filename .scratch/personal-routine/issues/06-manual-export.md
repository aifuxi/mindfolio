# 实现第一阶段私人数据手动导出

Status: completed

## 目标

让管理者手动下载包含第一阶段个人管理数据及保留历史的文件，供自行备份和查阅。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[技术实施规格](../../technical-plan/spec.md)、[完成历史 ADR](../../../docs/adr/0010-preserve-task-completion-history.md)。

## 实施范围

1. 提供仅管理者可访问的 UTF-8 JSON 下载接口，包含格式版本、生成时间、项目、任务与一级子任务、任务完成历史、习惯设定与暂停、打卡历史、每日记录。
2. 导出使用一致性数据库读取，保留业务日期原始 `YYYY-MM-DD`、时间点和字符串 ID；已删除任务或项目仍保留的完成记录必须包含在内。
3. 明确导出记录的结构及空数据语义；不导出密码哈希、Session、CSRF token 和其他认证秘密。响应禁止共享缓存，文件名包含导出日期。
4. 管理端提供手动导出操作与下载反馈；失败时不给出空文件或误报成功。
5. 更新契约，使用真实数据库与浏览器检查文件可下载、可解析、数据完整且权限正确。

## 验收条件

- 导出覆盖第一阶段范围内的现存内容与保留历史；下载 JSON 可解析，格式版本与日期、ID 可供后续识别。
- 导出读取期间并发写入不会造成跨表相互矛盾的数据；删除后的任务完成记录仍在文件中。
- 未登录请求被拒绝，导出内容无认证秘密、不会被共享缓存；失败响应不作为成功文件下载。
- 真实 PostgreSQL HTTP 测试、浏览器下载流程、契约检查与 `mise run ci` 通过。

## 依赖与交接

- 依赖任务 05，届时第一阶段私人业务数据结构已齐备。
- 本任务不实现数据导入、自动备份或第二阶段公开网站数据导出；公开站点信息、文章和友链在第二阶段接入导出。
- 验收后记录导出字段与检查结果，并单独提交。

## 验收记录

- 2026-09-28：`GET /export` 返回 UTF-8 JSON 附件，根对象包含 `format_version`、`generated_at`，以及 `projects`、`tasks`、`task_tags`、`task_tag_links`、`task_completions`、`habits`、`habit_settings`、`habit_pauses`、`habit_checkins`、`daily_journals` 十个数组。空数据仍输出全部数组，值为 `[]`。
- 导出字段包含现存对象及保留的任务完成历史；所有业务 ID 为十进制字符串，业务日期为 `YYYY-MM-DD`，时间点为 RFC 3339。认证表、密码哈希、Session 和 CSRF 信息不进入文件。
- 服务端在同一个 `REPEATABLE READ READ ONLY` 事务内读取全部业务表。私人路由统一设置 `Cache-Control: no-store`；文件名带上海业务日期。浏览器仅在成功响应后触发下载。
- `mise run ci` 通过，包含真实 PostgreSQL 空数据、完整数据、删除后完成记录、并发写入、权限与响应头测试，以及浏览器失败反馈和文件下载解析流程。
