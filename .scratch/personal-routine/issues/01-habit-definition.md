# 实现习惯设定与暂停

Status: ready-for-agent

## 目标

让管理者建立每天或每周指定天数的习惯，并管理暂停、恢复与设定变更，同时保留后续统计所需的历史语义。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[领域术语](../../../CONTEXT.md)。

## 实施范围

1. 建立习惯、设定历史与暂停区间的数据库迁移及私人 API；每天目标和每周 1 至 7 天目标互斥且可校验。
2. 管理端提供习惯列表、创建、编辑、暂停、恢复和历史查看入口；保存失败或 409 冲突时保留未提交输入。
3. 设定变更按上海业务日期生效，既有日期仍按当时设定解释。暂停与恢复形成无重叠日期区间；定义恢复当天是否应执行，并与 API、页面保持一致。
4. 删除习惯只使其退出当前列表；既有设定和后续打卡所需的历史标识保留。更新、暂停、恢复及删除使用预期版本。
5. 更新 OpenAPI 与 TypeScript 类型，测试私人边界、约束、版本和迁移。

## 验收条件

- 每天目标和合法每周目标可创建、编辑；非法目标、重叠暂停区间及创建前日期被拒绝。
- 暂停与恢复在上海业务日期上有一致边界；旧设定和旧暂停区间仍可查询，后续修改不会覆盖已发生的历史。
- 删除后当前习惯列表不再显示该习惯，历史所需数据仍在；未登录或无有效 CSRF 的写请求被拒绝，版本冲突返回 409。
- 真实 PostgreSQL HTTP 测试、契约漂移检查、管理端关键操作及 `mise run ci` 通过。

## 依赖与交接

- 依赖上一批 07“今日任务”已完成的私人 API 与业务时区基础。
- 本任务不实现打卡和完成率；向任务 02 提供可按日期解释的设定与暂停信息。
- 验收后记录实际生效日期语义和检查结果，并单独提交。
