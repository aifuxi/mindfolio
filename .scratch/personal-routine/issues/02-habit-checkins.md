# 实现习惯打卡、日历与完成率

Status: completed

## 目标

让管理者为当天或过去日期记录习惯完成情况和备注，并按既有设定查看打卡日历及周、月完成率。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[验收边界](../../technical-plan/testing-plan.md)。

## 实施范围

1. 建立每个习惯、每个业务日期唯一的打卡记录；支持完成、未完成、备注与更正，写入时校验暂停、创建日期、未来日期和预期版本。
2. 提供按习惯和日期区间查询打卡及服务端周、月统计的私人 API；日历明确区分已完成、明确未完成、漏打卡、暂停和未来日期。
3. 每天目标按已到来的非暂停应执行日计算完成率。每周目标按上海时间周一至周日计算有效目标与达成次数；月完成率按相交周的达成率，以落在当月的已到来应执行日期数加权平均。设定变化、暂停、跨月周及当前部分周均以相应日期的历史设定解释。
4. 管理端提供打卡、补记、更正、日历和周、月完成率；日期字段保持 `YYYY-MM-DD`，不经 UTC 时间戳中转。
5. 更新契约与真实数据库、浏览器关键流程测试。

## 验收条件

- 同一习惯同一日期不能产生重复打卡；补记和更正即时反映在日历与统计，备注保留；未来或暂停日期不能打卡。
- 普通漏打卡按未完成、暂停不进入分母，未来不提前降低当前完成率；每天和每周目标均给出可解释的分子、分母及百分比。
- 受控时钟覆盖上海跨日、周一、月末、跨月周、暂停和设定变更；被删除习惯的既有打卡仍可作为历史读取。
- 私人鉴权、CSRF、版本冲突、真实 PostgreSQL HTTP 测试、浏览器补记流程与 `mise run ci` 通过。

## 依赖与交接

- 依赖任务 01 的习惯设定历史与暂停区间。
- 向每日记录、“今日”和每周回顾提供按日期查询的打卡与统计语义。
- 验收后记录统计边界与检查结果，并单独提交。

## 验收记录

- 2026-09-27：打卡按习惯与业务日期唯一保存；新建使用空预期版本，更正必须携带当前版本。创建前、未来、暂停日期和已删除习惯拒绝新打卡；已删除习惯的旧记录仍可读取。
- 日历区分完成、明确未完成、漏打卡、暂停、未来、创建前及删除后。每周按同一设定生效片段计算有效目标；跨月周的月完成率按当月已到来的可执行日期数加权。无可执行日期返回无百分比。
