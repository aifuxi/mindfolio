# 实现“今日”的任务部分

Status: done

## 目标

让管理者在一个入口看到计划当天执行、当天到期和已逾期的未完成任务，并能主动把任务安排到今天。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[领域术语](../../../CONTEXT.md)、[技术实施规格](../../technical-plan/spec.md)。

## 实施范围

1. 服务端以固定 `Asia/Shanghai` 日期计算“今天”，聚合计划日期为今天、截止日期为今天或已逾期的未完成任务；同一任务符合多项条件时只出现一次，并保留可解释的提示信息。
2. 提供把收件箱或项目任务主动安排到今天的私人写接口或复用现有任务更新；该操作设置计划日期，不改动截止日期、项目归属或完成历史。
3. 管理端提供明确标为“今日任务”的入口，显示待办、已逾期与其他应处理任务，并可进入原任务详情。项目任务、收件箱任务及子任务按已确认的任务语义展示。
4. 更新契约和测试，以受控时钟或等价方式验证时区、跨日、去重和分页，不依赖运行测试当天的实际日期。

## 验收条件

- 计划今天、今天到期或已逾期且未完成的任务正确出现；完成或取消的任务不出现；同一任务不会重复展示，逾期提示与实际截止日期一致。
- 主动安排到今天后立即可见，原截止日期不变；未登录或缺少有效 CSRF、来源错误的写请求被拒绝，版本冲突返回 409。
- 在 UTC 与 `Asia/Shanghai` 日期不同的时间点仍以业务时区计算，浏览器不通过 UTC 转换改变 `YYYY-MM-DD` 日期。
- 真实 PostgreSQL HTTP 测试、关键页面流程、契约漂移检查与 `mise run ci` 通过。

## 依赖与交接

- 依赖任务 06，并复用已完成的任务查询与私人访问边界。
- 本任务只交付任务部分；待打卡习惯和当日每日记录在其模块完成后再接入完整“今日”。不增加站外提醒或虚构占位数据。
- 完成后记录业务时区边界与实际验收结果，并单独提交。

## 验收结果

- 私人 `GET /today/tasks` 由服务端按 `Asia/Shanghai` 计算业务日期，汇总计划今天、今天到期或已逾期的待办与进行中任务，并返回命中原因；同一任务仅出现一次，按逾期优先稳定分页。
- 私人 `POST /tasks/{id}/plan-today` 在预期版本校验后设置计划日期，收件箱与项目任务均可使用；重复安排保持版本，截止日期、项目归属和完成历史不变。管理端提供“今日任务”入口、安排操作及原任务详情跳转。
- 固定时钟的真实 PostgreSQL HTTP 测试验证 `2026-09-27T15:59:59Z` 属于上海 9 月 27 日，`2026-09-27T16:00:00Z` 属于上海 9 月 28 日；覆盖去重、逾期、完成与取消排除、分页、鉴权、CSRF、来源和版本冲突。浏览器测试验证安排后即时可见、截止日期保持原样及详情跳转；`mise run ci` 通过。
