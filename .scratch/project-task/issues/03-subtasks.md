# 实现一级子任务与父任务完成提示

Status: planned

## 目标

让管理者把任务拆为最多一级的子任务，分别跟踪其状态和日期，并在完成父任务时知晓仍有未完成的子任务。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[领域术语](../../../CONTEXT.md)。

## 实施范围

1. 在现有任务结构与迁移链上加入父子关系及必要索引和约束；服务端在事务中校验深度、归属项目、移动和状态变更，不允许子任务再拆分。
2. 子任务拥有自己的状态、计划日期和截止日期，可编辑、完成、重新打开，并沿用任务 02 的完成事实规则。
3. 管理端在任务详情中创建和维护子任务；管理者尝试完成父任务时，显示未完成子任务提示并允许其明确决定是否继续，不自动完成或取消子任务。
4. 更新 Rust DTO、OpenAPI、TypeScript 类型和必要页面测试。

## 验收条件

- 可创建一级子任务；给子任务添加子任务、形成环、让父子项目归属不一致或移动后出现不一致均被拒绝且无部分写入。
- 子任务的状态和日期可独立于父任务修改；父任务手动完成不改变子任务状态，仍有未完成子任务时页面给出提示。
- 子任务完成、重复提交及重新打开后再次完成遵循任务 02 的完成记录规则；并发冲突返回 409。
- 私人访问边界、真实 PostgreSQL HTTP 测试、关键页面流程和 `mise run ci` 通过。

## 依赖与交接

- 依赖任务 02。
- 本任务不增加第二级嵌套，也不实现自动汇总父任务状态。后续项目视图和删除行为须同时考虑子任务。
- 完成后记录层级与移动边界的验收结果，并单独提交。
