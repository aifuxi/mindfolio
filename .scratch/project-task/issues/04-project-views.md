# 实现项目看板、列表与任务检索

Status: planned

## 目标

让管理者在同一项目切换看板与列表，并按条件找到任务。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[技术实施规格](../../technical-plan/spec.md)。

## 实施范围

1. 管理端为同一项目提供看板和列表两种视图，两者使用同一批服务端任务数据；待规划区与任务状态分开展示，不创造第五种状态。视图切换不修改任务。
2. 建立任务标签的真实数据关系及迁移；任务标签与文章标签保持独立。提供设置、移除和按标签筛选的私人 API。
3. 提供有上限分页、稳定排序的任务查询，支持关键词、状态、优先级、计划日期、截止日期和任务标签筛选。使用参数化 SQL 与必要索引；收件箱、项目任务及子任务的范围明确。
4. 生成并检查 Rust DTO、OpenAPI 和 TypeScript 类型；把查询与视图切换的关键行为接入 `mise run ci`。

## 验收条件

- 同一项目的看板和列表展示一致的任务及子任务状态；切换视图不改变持久化数据。待规划区不会被误写成任务状态。
- 不同筛选条件可组合使用，分页有上限且排序稳定；关键词与标签筛选结果正确，未登录无法读取搜索结果。
- 真实 PostgreSQL HTTP 测试、必要浏览器交互测试、契约漂移检查及 `mise run ci` 通过。

## 依赖与交接

- 依赖任务 03。
- 本任务不实现全局搜索、文章标签或 Markdown 预览；后者在任务 05 独立验收。管理端视图继续使用已有私人 API 与 Session 边界。
- 完成后记录筛选与分页的验收结果，并单独提交。
