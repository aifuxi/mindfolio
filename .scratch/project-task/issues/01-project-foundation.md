# 建立私人资源边界与项目管理

Status: done

## 目标

让唯一管理者在登录后创建、查看、整理项目，并为后续所有私人业务 API 建立可复用的服务端身份与写请求保护。

依据：[本批规格](../spec.md)、[技术实施规格](../../technical-plan/spec.md)、[领域术语](../../../CONTEXT.md)、[登录 ADR](../../../docs/adr/0006-local-account-postgresql-session.md)。

## 实施范围

1. 将现有认证代码整理为业务路由可复用的私人访问边界。每次私人读取验证 Session；每次状态修改同时验证 Session、CSRF token 和来源。公开存活接口仍可匿名访问，错误保持统一 DTO。
2. 通过版本化迁移建立项目实体、必要约束与索引，采用 `BIGINT IDENTITY`、独立的完成与归档信息，以及实体版本。项目名称与其他输入在服务端验证。
3. 实现项目创建、列表、详情、修改、标记完成、归档和恢复的私人 API。归档保留项目，恢复后保留原有完成信息；删除留给任务 06。
4. 将 Rust DTO、OpenAPI、TypeScript 类型及管理端请求串起；管理端提供实际可用的项目列表、创建与整理入口，登录失效时回到登录页。
5. 使用真实 PostgreSQL 和 HTTP 验证访问边界、数据约束、版本冲突及项目状态，并把必要的页面行为接入 `mise run ci`。

## 验收条件

- 未登录或过期会话不能读取、创建或修改项目；缺少或错误的 CSRF token、来源不匹配的写请求均被拒绝；合法同源请求可完成。公开 `/health/live` 不受影响。
- 管理者可创建并查看项目、修改名称、标记完成、归档与恢复；归档不删除项目，恢复后数据和完成信息仍在。
- 空库迁移、约束、字符串 ID、版本校验和 409 冲突经真实 PostgreSQL 与 HTTP 验证；不存在的项目返回 404，冲突时管理端不丢失编辑输入。
- 生成契约与管理端类型一致；`mise run ci` 对新 API、页面和数据库检查真实通过。
