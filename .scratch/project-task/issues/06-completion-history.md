# 实现完成历史查询及删除后保留

Status: planned

## 目标

让管理者回看任务曾经完成的事实，并在删除任务或项目后继续通过每日汇总看到既有完成记录。

依据：[本批规格](../spec.md)、[功能范围](../../product-scope/spec.md)、[完成历史 ADR](../../../docs/adr/0010-preserve-task-completion-history.md)。

## 实施范围

1. 基于任务 02、03 已写入的完成记录，提供私人历史查询和按 `Asia/Shanghai` 业务日期归属的每日任务完成汇总。展示完成时刻及当时的任务标题、项目名称快照；任务与项目后续更名不改写旧记录。
2. 实现任务、子任务和项目删除的私人 API 与管理端操作。删除后相关当前内容退出列表与详情；既有完成记录保留，不能因外键级联丢失。项目归档仍是可恢复操作，与删除语义分开。
3. 处理父子任务和项目删除的事务边界、预期版本、重试及并发冲突。不存在或已删除资源返回 404；管理端在确认删除前说明当前内容与历史的不同处理。
4. 在管理端提供可查看的完成历史与每日汇总入口；已删除对象的历史不提供可操作的当前详情链接。
5. 更新契约，并通过真实 PostgreSQL 与浏览器关键路径验证完成、重新打开、删除及历史保留。

## 验收条件

- 完成任务或子任务后可查看记录；重新打开与更名不删除或回写旧记录，再次完成可增加新记录。重复提交同一次完成不会产生重复事实。
- 删除任务、子任务或项目后，当前列表和详情不再出现相关对象，已有完成记录仍可按原日期查询，并保留必要名称快照；归档项目可恢复且不等同删除。
- 跨 UTC 日期边界的完成时刻按 `Asia/Shanghai` 归入正确业务日期。删除与并发更新发生冲突时返回 409，数据库无部分删除。
- 历史查询仅管理者可访问；真实 PostgreSQL HTTP 测试、浏览器完成与删除后回看流程、`mise run ci` 通过。

## 依赖与交接

- 依赖任务 05；使用任务 02、03 的完成记录机制和父子关系。
- 本任务不实现每周回顾、导出、回收站或全量审计。后续每日记录和每周回顾使用这里的历史查询语义。
- 完成后记录删除与历史保留的实际验收结果，并单独提交。
