# 项目任务首批业务闭环规格

Status: ready-for-agent

## 问题陈述

管理者目前只能登录私人管理端，还不能把临时事项放进收件箱、按项目组织任务、推进子任务或回看已完成的工作。登录后的页面需要逐步成为可用的个人管理入口，同时保证私人数据、完成历史和日期语义符合已确认的技术与产品约定。

依据：[功能范围](../product-scope/spec.md)、[技术实施规格](../technical-plan/spec.md)、[验收边界](../technical-plan/testing-plan.md)、[领域术语](../../CONTEXT.md)、[完成历史 ADR](../../docs/adr/0010-preserve-task-completion-history.md)、[主键 ADR](../../docs/adr/0002-postgresql-identity-primary-keys.md)、[后端 ADR](../../docs/adr/0004-rust-modular-monolith.md)。

## 解决方案

先交付项目、收件箱、任务与一级子任务的完整操作链，再提供同一项目的看板和列表、搜索筛选、任务说明预览、完成历史以及“今日”的任务部分。每个增量都经 Rust 私人 API、真实 PostgreSQL 和管理端交互验证；后续习惯与每日记录模块再接入完整的“今日”入口。

## 用户故事

1. 作为管理者，我希望创建和整理项目，以便按共同成果组织任务。
2. 作为管理者，我希望标记项目完成、归档和恢复，以便区分当前工作和保留的历史。
3. 作为管理者，我希望先把临时任务放入收件箱，再将其归入项目，以便快速记录后整理。
4. 作为管理者，我希望在项目中创建、编辑和推进任务，以便跟踪标题、说明、状态、优先级和日期。
5. 作为管理者，我希望用待规划区单独存放尚未进入执行流程的项目任务，以便不把它误认为一种任务状态。
6. 作为管理者，我希望将任务拆成一级子任务并分别安排状态和日期，以便跟踪实际步骤。
7. 作为管理者，我希望在完成父任务时看到未完成子任务的提示，以便自行决定是否仍要完成父任务。
8. 作为管理者，我希望在同一项目中切换看板和列表，以便按不同方式查看同一批任务。
9. 作为管理者，我希望按关键词、状态、优先级、日期和任务标签筛选，以便找到要处理的任务。
10. 作为管理者，我希望编辑和安全预览 Markdown 任务说明，以便写清列表和代码片段。
11. 作为管理者，我希望任务每次从非完成状态进入已完成时留下完成事实，以便日后回顾。
12. 作为管理者，我希望重新打开任务后仍保留既有完成记录，以便历史不会被当前状态改写。
13. 作为管理者，我希望删除任务或项目后继续看到已有完成历史，以便每日汇总仍反映已发生的事情。
14. 作为管理者，我希望在“今日任务”看到计划当天执行、当天到期和已逾期的未完成任务，以便决定当天行动。
15. 作为管理者，我希望主动把任务安排到今天，以便不依赖截止日期来表达执行计划。
16. 作为管理者，我希望所有这些内容只对自己可见，并在冲突时保留未提交的输入，以免覆盖新的数据。

## 实施决策

- 沿用唯一管理者的服务端 Session。项目、任务、子任务、完成记录和“今日任务”接口均为私人 API；每次读取验证 Session，每次状态修改验证 Session、CSRF token 与请求来源。首项任务先建立可复用的私人路由边界，后续业务模块共用。
- 后端按项目任务与任务完成记录组织模块，HTTP DTO 与数据库模型分离。业务主键使用 PostgreSQL `BIGINT IDENTITY`；OpenAPI 和 TypeScript 对外将资源 ID 表示为十进制字符串。
- 收件箱任务暂不属于项目；待规划区只适用于已归入项目的任务，且独立于待办、进行中、已完成、已取消四种状态。一级子任务不能再有子任务；移动、层级及项目归属在事务中保持一致。
- 计划日期和截止日期为业务日期；“今日”由服务端按 `Asia/Shanghai` 计算。实际完成时间以 UTC 时刻保存，按业务时区归属到每日汇总。
- 任务进入已完成时，在同一事务中更新当前状态并追加任务完成记录。重复提交同一次完成不追加第二条；重新打开后再次完成可产生新记录。完成记录保存必要的任务与项目名称快照，后续修改或删除不回写历史。
- 项目归档与删除是不同操作。归档保留项目及任务以便恢复；删除使当前列表和详情不再出现相关内容，但不删除既有完成记录。完成记录不是全量操作审计或回收站。
- 更新与删除携带预期版本并原子校验；版本冲突返回 409，已删除或不存在的资源返回 404。前端保留冲突时的编辑输入。列表设置上限、稳定排序与 ID 同序条件；搜索使用参数化查询及必要索引。
- 任务说明保存 Markdown 原文，预览关闭原始 HTML，限制危险链接协议和远程图片加载。任务标签与文章标签分属不同概念。
- “今日任务”只交付任务部分：符合计划当天、当天到期或已逾期条件的未完成任务去重展示，并允许主动安排到今天。习惯和每日记录完成后再扩展完整“今日”入口，不显示虚构数据。
- Rust DTO 是接口结构唯一来源。每项任务修改 DTO 后生成 OpenAPI 与 TypeScript 类型，继续通过 `mise run ci` 做漂移、类型、格式、lint、测试和构建检查。

## 测试决策

- 首选 HTTP 与隔离的真实 PostgreSQL 边界，验证私人鉴权、CSRF、约束、事务、版本冲突、完成记录、删除保留和跨日期归属；延续现有认证集成测试的方式。
- 浏览器测试只串联管理者关键路径：登录后创建项目和任务、完成与重新打开、查看历史、删除后回看、切换视图及查看“今日任务”。管理端路由保护与 Rust API 权限分别验证。
- Markdown 预览通过可观察的浏览器行为验证危险 HTML、脚本链接和远程图片不会执行或加载；不重复测试解析库内部实现。
- 每个 issue 以其验收条件独立通过，并将新增的真实检查接入 `mise run ci`；不以空实现或占位测试宣称整批完成。

## 范围之外

- 习惯、打卡、每日记录、完整“今日”、每周回顾与手动导出；在后续业务批次单独拆分。
- 公开网站、文章、文件、访客接口、站外提醒和自动重复任务。
- 多管理者、团队协作、任务多级嵌套、回收站、全量操作审计和历史名称自动回写。
